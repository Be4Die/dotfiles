# ADR 002: Переход на загрузчик Limine и интеграция со снапшотами Snapper (Btrfs)

> **Дата:** Октябрь 2026 г.  
> **Статус:** Принято / Реализовано  
> **Затронутые хосты:** `desktop` (`cachyos-pc`)  
> **Компоненты:** Загрузчик Limine, `limine-snapper-sync`, Snapper, Btrfs, ESP (8GB), Nvidia GPU

---

Этот документ описывает полный процесс перехода с загрузчика GRUB на **Limine**, настройку автоматической генерации пунктов загрузки для снапшотов **Snapper** в Btrfs, решение проблемы нехватки места на EFI-разделе и устранение аппаратной проблемы с выводом экрана загрузки на неосновной монитор.

---

## 1. Контекст системы

* **ОС:** CachyOS Linux (Arch-based rolling release)
* **Файловая система:** Btrfs (корень `/@`, сабволюмы `/@root`, `/@srv`, `/@cache`, `/@tmp`, `/@log`)
* **Диск системы (`sda`):** 480 GB SSD (Kingston SA400)
* **Диск с данными (`sdb`):** 480 GB SSD (Crucial BX500) — смонтирован в `/home`
* **Материнская плата:** MSI B360M MORTAR (MS-7B23), BIOS v1.D0
* **Видеокарта:** Gigabyte NVIDIA GeForce GTX 1060 6GB (GP106)
* **Мониторы:**
  * Основной: HDMI (`card1-HDMI-A-1`)
  * Второстепенный (вертикальный): DVI (`card1-DVI-D-1`)

---

## 2. Архитектурная разница между GRUB и Limine для снапшотов

### Как работал GRUB:
* GRUB включает собственный драйвер файловой системы Btrfs.
* При загрузке в снапшот утилита `grub-btrfs` генерирует пункты меню, указывающие прямо на ядро внутри подтома Btrfs (`/.snapshots/.../snapshot/boot/vmlinuz-*`).
* Место на EFI-разделе (ESP) для снапшотов **не расходуется вообще**. Раздела в 512 МБ было достаточно.

### Как работает Limine + `limine-snapper-sync`:
* Limine на этапе первичной загрузки не парсит динамические вложенные сабволюмы Btrfs.
* Для обеспечения 100% надёжности и независимости версий (чтобы предотвратить рассинхронизацию обновлённого ядра в `/boot` и старых модулей ядра внутри снапшота), утилита `limine-snapper-sync` **копирует ядро (`vmlinuz`) и `initramfs` прямо на EFI-раздел (ESP)** для каждого загрузочного снапшота.
* С установленными драйверами NVIDIA (`nvidia-dkms`) каждый образ initramfs весит **~190 МБ**.
* **Вывод:** На исходном разделе EFI размером 512 МБ два установленных ядра (`linux-cachyos` и `linux-cachyos-lts`) занимали ~413 МБ (81%). Места для хранения ядер снапшотов не оставалось.
* **Требование:** Для комфортной работы Limine со снапшотами необходим EFI-раздел размером **от 4 до 8 ГБ**.

---

## 3. Расширение EFI-раздела (ESP) до 8 ГБ

### Почему нельзя расширить «на живой» системе:
Разделы на диске `sda` располагались вплотную:
* `sda1` (ESP, FAT32): сектор 2048 – 1050623 (512 МБ)
* `sda2` (Btrfs root): сектор 1050624 – 937703087 (479.5 ГБ)

Уменьшение Btrfs «на лету» (`btrfs filesystem resize`) высвобождает место только в **конце** раздела. Чтобы отдать место разделу `sda1`, требуется **сдвинуть начальный сектор раздела `sda2` вправо**. Сдвиг начала смонтированного корневого раздела активным ядром Linux заблокирован во избежание повреждения ФС.

### Выполнение через GParted Live (на флешке Ventoy):
1. Скачан образ `gparted-live-amd64.iso` и скопирован на флешку Ventoy.
2. Загрузка в GParted GUI.
3. Раздел `sda2` (Btrfs) $\to$ **Resize/Move** $\to$ поле *Free space preceding* = `8192` (сдвиг начала раздела вправо на 8 ГБ).
4. Раздел `sda1` (FAT32) $\to$ **Resize/Move** $\to$ растянут вправо на всё освободившееся пространство (до 8.0 ГБ).
5. Нажата кнопка **Apply**.
6. Так как `/home` физически изолирован на `sdb`, личные данные не подвергались риску. UUID разделов (`sda1`: `B577-F4F8`, `sda2`: `745989c7-...`) полностью сохранились, поэтому `/etc/fstab` остался актуальным.

## 4. Установка и настройка Limine

### 4.1. Установка пакетов
В CachyOS необходимые инструменты доступны в официальных репозиториях:
```bash
sudo pacman -S limine limine-mkinitcpio-hook limine-snapper-sync inotify-tools snap-pac
```
* `limine` — современный мультипротокольный загрузчик.
* `limine-mkinitcpio-hook` — хук автоматизации ядра для Limine (`limine-update`, `limine-install`).
* `limine-snapper-sync` — сервис синхронизации точек восстановления Snapper с меню Limine.
* `inotify-tools` — отслеживание создания/удаления снапшотов демоном `limine-snapper-watcher`.
* `snap-pac` — автоматическое создание pre/post снапшотов при каждой транзакции pacman.

### 4.2. Хук OverlayFS для загрузки в Read-Only снапшоты
Снапшоты Btrfs монтируются в режиме «только чтение». Чтобы система (systemd, дисплейный менеджер) могла корректно стартовать в такой снимок, необходим временный слой записи в оперативной памяти (OverlayFS).

В файле `/etc/mkinitcpio.conf` в массив `HOOKS=(...)` после `filesystems` добавлен `sd-btrfs-overlayfs`:
```text
HOOKS=(base systemd autodetect microcode kms modconf block keyboard sd-vconsole plymouth filesystems sd-btrfs-overlayfs)
```

### 4.3. Первичная инициализация и сборка
```bash
# Установка EFI-бинарника Limine в ESP и регистрация в NVRAM
sudo limine-install

# Пересборка initramfs с хуком оверлея и генерация /boot/efi/limine.conf
sudo limine-update

# Включение службы фоновой синхронизации снапшотов
sudo systemctl enable --now limine-snapper-sync.service

# Включение таймера автоматической очистки старых снимков
sudo systemctl enable --now snapper-cleanup.timer

# Первичная ручная синхронизация
sudo limine-snapper-sync
```

## 5. Полное удаление GRUB и настройка тайм-аута

После подтверждения успешной работы Limine старый GRUB был удален:

1. **Удаление пакетов GRUB:**
   ```bash
   sudo systemctl disable --now grub-btrfs-snapper.path
   sudo pacman -Rns grub grub-btrfs grub-btrfs-support grub-hook cachyos-grub-theme
   ```

2. **Очистка каталогов и записей NVRAM:**
   ```bash
   # Удаление остатков GRUB с диска
   sudo rm -rf /boot/efi/EFI/cachyos /boot/grub

   # Удаление старой записи из памяти материнской платы
   sudo efibootmgr -b 0002 -B

   # Установка Limine первым в приоритете загрузки
   sudo efibootmgr -o 0000,0008,0006,0001

   # Установка Limine как стандартного fallback-загрузчика (на случай сброса NVRAM платой)
   sudo limine-install --fallback
   ```

3. **Увеличение задержки меню Limine:**
   В файле `/boot/efi/limine.conf` тайм-аут изменён с 3 до 10 секунд:
   ```text
   timeout: 10
   ```

## 6. Решение проблемы с выводом экрана BIOS и загрузчика на вертикальный монитор (DVI vs HDMI)

### Симптом:
Логотип материнской платы при старте ПК и меню загрузчика Limine отображались на старом вертикальном мониторе, подключённом по DVI, а не на основном HDMI-мониторе.

### Причина:
1. **Аппаратный приоритет портов GPU (NVIDIA Pascal / GTX 1060):**  
   В микрокоде VBIOS видеокарты физически зашит порядок опроса видеовыходов при старте:
   $$\mathbf{DVI} \longrightarrow \mathbf{DisplayPort} \longrightarrow \mathbf{HDMI}$$
   Видеокарта опрашивает порт DVI первым. Обнаружив на нём устройство, VBIOS передаёт этот порт материнской плате как основной для протокола UEFI GOP (Graphics Output Protocol). Никакой загрузчик не может переключить экран до загрузки драйверов ядра.
2. **Задержка цифрового рукопожатия (HDMI Handshake):**  
   DVI заявляет о наличии монитора за 0 мс. HDMI-монитор в режиме энергосбережения тратит от 1 до 2.5 секунд на пробуждение и опрос EDID. Видеокарта опрашивает шину за первые 500 мс — HDMI ещё «спит», поэтому видеокарта считает его неподключенным.
3. **Почему на Windows этого не было заметно:**  
   В Windows по умолчанию включен *Fast Startup* (гибридная гибернация). При включении ПК полный опрос устройств (холодный POST) пропускается, и видеодрайвер Windows моментально отдаёт картинку на монитор, помеченный в системе как «Основной».

### Решения:
1. **Настройки монитора (программное решение задержки):**  
   В экранном меню (OSD) самого монитора выключить режим *Auto-Detect Input* и жёстко зафиксировать вход *HDMI 1*. Монитор просыпается моментально и успевает ответить видеокарте во время POST.
2. **Настройки BIOS платы MSI B360M MORTAR:**  
   * *Settings $\to$ Advanced $\to$ Windows OS Configuration*: режим **UEFI** (выключить CSM).
   * *Settings $\to$ Boot $\to$ MSI Fast Boot / Fast Boot*: скорректировать тайминги опроса устройств.
3. **Аппаратное подключение через DisplayPort (100% надёжность):**  
   Подключение основного монитора к первому порту DisplayPort (`DP-1`) на GTX 1060 (напрямую кабелем DP или переходником DP $\to$ HDMI) даёт ему наивысший приоритет над DVI.

## 7. Памятка по командам

* `limine-snapper-list` — просмотр списка снапшотов, добавленных в меню Limine.
* `limine-snapper-sync` — ручная принудительная синхронизация снапшотов Snapper с Limine.
* `limine-snapper-restore` — интерактивный откат системы на выбранный снапшот после загрузки в него.
* `limine-update` — пересборка initramfs и обновление записей всех установленных ядер в `/boot/efi/limine.conf`.
* `snapper list` — полный список снапшотов Btrfs в системе.
