# Системная память и реестр решений (docs/memory/)

В этом каталоге хранятся архитектурные решения (ADR), фиксы нетривиальных системных проблем и зафиксированные предпочтения пользователя.

---

## 📌 Зачем нужен этот каталог?

Пользователь редко настраивает систему вручную. AI-агент, работающий с системой, обязан опираться на эту базу знаний, чтобы:
1. **Не повторять старых ошибок** (например, не пытаться включить подсветку на MacBook через `xbacklight` или программный димминг, зная про блокировку I/O портов мостом AMD).
2. **Не ломать утвержденные стандарты** (например, помнить, что весь локальный трафик прокси стандартизирован на порту `7890`).
3. **Знать контекст каждого решения:** почему выбран именно этот инструмент, какие альтернативы отброшены и почему.

## ✍️ Правила создания новой memory-заметки

Каждый раз, когда агент решает сложную проблему или внедряет архитектурное изменение, создается файл `docs/memory/NNN-название-на-английском.md`:

```markdown
# ADR NNN: Название решения

> **Дата:** Месяц Год  
> **Статус:** Принято / В процессе  
> **Затронутые хосты:** desktop / laptop / all  
> **Компоненты:** Названия пакетов или демонов  

---

## 1. Контекст и проблема
Что не работало или почему возникла необходимость изменений? Какие ограничения были?

## 2. Принятое решение
Что именно было сделано (конфиги, команды, юниты systemd, правила udev)?

## 3. Последствия и правила для агента
Что теперь агент ОБЯЗАН помнить при дальнейшей работе?
```

После создания файла обязательно добавьте строку в таблицу выше!
